# Checklist de cierre institucional

## A. Despliegue y enlaces

- [ ] Repositorio publicado en GitHub Pages.
- [ ] URL principal abre sin autenticación.
- [ ] Las seis páginas independientes abren mediante enlace directo.
- [ ] Se incluyó el enlace de la micropágina desde la sede electrónica municipal.
- [ ] Se verificaron enlaces, documentos y botones en computador y celular.

## B. Decisiones de impacto ciudadano

- [ ] Cada decisión contiene título, tipo, número y fecha.
- [ ] Se publicó resumen o contenido relevante.
- [ ] Se publicaron fundamentos jurídicos y técnicos.
- [ ] Se explicó impacto y población interesada.
- [ ] Se identificó responsable, estado, procedimiento y canales.
- [ ] El documento oficial está enlazado directamente.

## C. Supervisión

- [ ] Se identificaron mecanismos internos de supervisión.
- [ ] Cada mecanismo contiene responsable, procedimiento, frecuencia y canal.
- [ ] Se enlazaron informes o evidencias vigentes.
- [ ] Se publicó directorio de organismos externos y tipo de control.
- [ ] Los datos de contacto se verificaron en la fuente oficial.

## D. Hojas de vida

- [ ] La sección permanente está publicada aun cuando no haya proceso activo.
- [ ] Cada proceso real publica cargo, dependencia y fundamento.
- [ ] La hoja de vida fue anonimizada antes de publicarse.
- [ ] Se indicó fecha y hora de apertura y cierre.
- [ ] El canal de observaciones funciona.
- [ ] Al cerrar el proceso se conservó el archivo histórico.

## E. Gaceta Oficial

- [ ] La sección se identifica expresamente como Gaceta Oficial Municipal.
- [ ] Los actos tienen fecha, tipo, número, título, estado y enlace.
- [ ] La búsqueda y los filtros funcionan.
- [ ] Los actos anteriores se conservan aunque cambie su vigencia.
- [ ] Se registran nuevas publicaciones de forma continua.

## F. Agenda Regulatoria

- [ ] La agenda está aprobada por la instancia institucional competente.
- [ ] Las iniciativas están en orden cronológico.
- [ ] Cada ficha contiene objetivo, impacto, responsable y periodo de consulta.
- [ ] Se identifica estado y expediente relacionado.
- [ ] Las adiciones y modificaciones se registran en el historial.
- [ ] Se creó la agenda de la nueva vigencia antes de reemplazar la anterior.

## G. SUCOP y participación normativa

- [ ] La solicitud de habilitación se encuentra documentada.
- [ ] El canal local de proyectos y observaciones permanece activo.
- [ ] Los proyectos incluyen plazo, responsable y documentos.
- [ ] Se publica registro de comentarios y respuesta anonimizada.
- [ ] Al recibir la URL del DNP, se pegó en Administración → Configuración.
- [ ] La página muestra el enlace directo al perfil o proceso institucional en SUCOP.

## H. Firebase y seguridad

- [ ] Google Authentication está habilitado.
- [ ] El dominio GitHub Pages está autorizado.
- [ ] Las reglas `firestore.rules` están desplegadas.
- [ ] Solo administradores autorizados pueden editar.
- [ ] Las observaciones y datos de contacto no son de lectura pública.
- [ ] Las respuestas públicas están anonimizadas.
- [ ] El registro de auditoría funciona.

## I. Publicación en la matriz ITA

- [ ] Se usó el enlace directo de cada página, no la portada genérica.
- [ ] La descripción de evidencia identifica contenido, fecha y dependencia.
- [ ] La evidencia SUCOP solo se marca como cumplida cuando exista el enlace directo real.
- [ ] Se conservaron capturas y una copia exportada de la fecha de verificación.

## Talento Público Abierto

- [x] Fuente permanente y directa para el directorio de funcionarios.
- [x] Enlaces a perfiles institucionales y consulta SIGEP II.
- [x] Sección independiente para hojas de vida en consideración ciudadana.
- [x] Periodos de observaciones visibles cuando existan procesos activos.
- [x] Canal ciudadano individual por funcionario o proceso.
- [x] Código de seguimiento y respuesta pública anonimizada.
- [x] Sincronización diaria mediante GitHub Actions.
- [x] Conservación de la última versión válida si la fuente no responde.
- [x] Protección de datos mediante enlaces a versiones públicas de origen.
